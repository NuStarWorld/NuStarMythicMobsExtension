# nustarthreat：修改本插件的威胁记录

## 用途

让一个生物更在意施法者，或者把施法者积累的威胁转给另一个实体。它修改的是 **NuStar 自己维护的记录**，不是 MM 原生的 `ThreatTable`。

先记住方向：牛 A 对僵尸 B 使用 `nustarthreat{mode=add;amount=10}`，改的是 **B 的表里，A 的分数**，不是 A 的表里 B 的分数。选玩家作为 `add` 目标不会替这名玩家给自己加仇恨。

## 准备

- 安装本扩展与对应 MM 适配，使用前确认本服版本。
- 施法者与技能目标都要有生命值；`add/set/delete/top` 的目标只适用于僵尸、牛、村民这类生物，玩家、盔甲架等不适用，也不是所有有生命值的实体都支持。
- 不要求开启 MM 的 `Modules.ThreatTable`，开启它也不会把两套记录合并。若另有 AI/仇恨插件参与，需单独确认最终攻击目标。
- 这项技能修改记录时**不会主动改变攻击目标**。不要把 `top` 理解为保证立即转头攻击。生物受伤时，本插件还可能更新记录和攻击目标，但最终结果也受怪物行为和其他插件影响。

## 参数

| 参数 | 简写或其他写法 | 不填写时 | 填写说明与效果 |
| --- | --- | --- | --- |
| `mode` | `m`，不建议使用 | `add` | 填小写 `add`、`set`、`delete`、`top`、`transfer`，具体方向见下表。不是 `true/false`。 |
| `amount` | `a` | `0` | 填威胁分数或本插件算式，无距离或时间单位。计算后转为长整数，小数部分截去；只对 `add/set` 有实际数值作用。 |
| `multiple` | 与 `mode` 共用 `m`，不要使用短名 | `1` | 源码读取了这一项，但执行时没有使用；填 `2` **不会翻倍**。建议整个参数不填。 |

**`mode/m` 与 `multiple/m` 短名冲突。** 请写 `mode=add;amount=10`，不要写 `m=2` 当作倍率，也不要依赖 `m=add` 同时被另一参数读取时的行为。

| 模式 | 改谁的表、改谁的分数 |
| --- | --- |
| `add` | 给技能目标的表中「施法者」加 `amount`；负数按加 0 处理，不能用负数减分。 |
| `set` | 把技能目标的表中「施法者」设成 `amount`；负数按 0 处理。设成 0 不等于删除。 |
| `delete` | 从技能目标的表中移除「施法者」这一项。 |
| `top` | 把技能目标的表中「施法者」设为当前最高分 + 1；空表时设为 1。 |
| `transfer` | 遍历插件**当前已记录的所有生物表**，把「施法者」的分数加到「技能目标」已有分数上，再把施法者分数设成 0。不是只转移某一头怪的表，也不是复制整张表。目标若是 MM 生物，服务层会直接跳过。 |

## 记录为什么自己变化

以下是当前行为，不是拟修方案。即使没有额外使用这项技能，受伤、死亡和切换目标也会影响观察：

- **受伤自动记分：** 只识别 MM 的僵尸、牛、村民这类生物（`Creature`），按本次实际伤害转成整数给直接攻击者记分，小数部分截去。当前没有跳过已取消的伤害，取消伤害仍可能记分。箭命中时记的是箭，不会追溯射手；随后还会尝试设置攻击目标。
- **死亡自动转移或清理：** 玩家死亡时，如果有玩家击杀者，就把当前所有已记录表中死者的分数转给击杀者，再清理死者的记录；没有玩家击杀者也会清理死者记录。上述生物死亡时，会清掉它自己的威胁表。
- **第一名不等于最终攻击目标：** 当前 MM 生物切目标时，若准备切换到的目标正好是记录第一名，这次切目标事件反而会被取消。不能把“记录第一名”当成“最后一定攻击谁”，也不能把 `top` 当成保证立即转头。

## 简短例子

在隔离测试服让一个 MM 村民被**普通僵尸近战攻击**。将完整技能组放入 MM 的 `Skills` 文件：

```yaml
NSDocsThreatAdd:
  Skills:
    - nustarthreat{mode=add;amount=10} @EntitiesInTargets
```

在那个 MM 村民的实体配置 `Skills` 中加：

```yaml
# 攻击者必须是普通僵尸等符合要求的生物，不要用玩家攻击验证此例。
# 村民受伤还会自动给攻击者记分，可能影响观察；那是村民自己的表，方向不同。
- skill{s=NSDocsThreatAdd} @trigger ~onDamaged
```

村民是施法者，僵尸是目标。本次 `@trigger` 由僵尸攻击提供，再传入技能组，因此**给僵尸的表中「村民」加 10**。村民受伤时，本插件也可能另外更新村民自己的表，这是另一方向的记录。普通僵尸会主动攻击村民；请在夜间或遮阳处安排测试并给村民足够生命值。

完整五种模式见 [threat-skills.yml](../examples/threat-skills.yml)。测试时一次挂接一种模式，避免相互覆盖；无需为了此例启用原生威胁表。

## 常见问题

- **为什么打玩家没变化？** 前四种模式只适用于僵尸、牛、村民这类生物，玩家、盔甲架等不适用。若想给怪物记录玩家的分数，需要在技能实际调用时让玩家成为施法者、怪物成为目标，不能简单对怪物用 `@self` 替代。
- **为什么 `m=2`、`multiple=2` 不翻倍？** 短名冲突，且倍率未参与计算。直接调整 `amount`。
- **为什么 `ADD` 无效？** 模式值按小写精确比较；未知模式没有实际操作，但可能仍返回成功，不能用“无报错”判断已改表。
- **为什么删除或转移仍报算式错误？** 所有模式都会先计算 `amount`，即使该模式不用数值。无须数值的模式不要填复杂算式。
- **转移为什么不生效？** 目标不能是 MM 生物；没有先前记录也没有有效分数可转。此操作对所有已记录表生效，别拿生产环境试验。
