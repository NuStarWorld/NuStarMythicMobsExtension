# `<nustar.threat.top>`：查看触发者的威胁第一名

> **警告：当前有卡服风险，暂不建议启用；特别不能简单加 `sync=true`；修复并验证后再用。**
>
> 只要表里已有第一名，当前实现就会等待一个需要服务器主线程执行的查询。如果消息正好在主线程展开，主线程可能一直等自己，导致服务器卡住。“先置顶，再发消息”会进入这个危险分支，不能作为当前可用方案。下方只保留功能说明和待修复参考，不要启用，也不要仅靠调整执行线程尝试绕过。

## 用途

功能含义：在 MM 消息中显示一个生物威胁记录第一名的实体名称。它优先读取 **NuStar 自己的威胁表**，不是 MM 原生 `ThreatTable`；返回的是名称文字，不是分数、UUID 或可用作算式的数字。记录第一名不等于最终攻击目标。

最重要的区别：查询的是本次技能的**触发者**，不是施法者，也不是消息接收者。把消息后的目标选择器换成 `@self`、`@target` 不会改变查询对象。

## 准备（修复并验证后再考虑）

- 需要本扩展、`minecraft-next` 和对应 MythicMobs；此占位符不要求 AP、SX 或 PlaceholderAPI。
- 先修复卡服风险并验证，再确认本服 MM 与扩展版本，不要因依赖齐全就启用。
- 本次技能必须确实带有一个有生命值的触发者；要查询威胁表，该触发者还须是僵尸、牛、村民这类生物，玩家、盔甲架等不适用，也不是所有有生命值的实体都支持。
- 不必开启 MM 原生威胁表，也不能用开启它来代替 NuStar 记录。

## 名称与返回值

下表仅说明待修复功能的含义，不保证当前能安全返回，尤其是已有第一名记录的分支。

| 参数或名称 | 不填写时或值 | 说明 |
| --- | --- | --- |
| 完整写法 | `<nustar.threat.top>` | 用于支持 MM 占位符的文字参数，例如 `message` 的消息内容；不是 `%nustar_threat_top%`。 |
| 参数 | 无 | 无 `target`、半径或默认文字参数，不能在这里指定另一个查询对象。 |
| 查询对象 | 本次触发者 | 下方参考中是攻击村民的普通僵尸。 |
| 有最高分记录且实体仍能找到 | 该实体的名称 | 名称由服务器实体提供；同分不保证固定顺序。此分支当前有卡服风险。 |
| 有最高分记录，但找不到对应实体 | `无目标` | 这种情况不会再改用当前 AI 目标兜底；同样会经过有卡服风险的查询。 |
| 威胁表没有第一名，但生物当前有 AI 目标 | 当前目标的名称 | 即使 NuStar 表为空，也可能显示名称，不代表已经有威胁分数。 |
| 威胁表没有第一名，且没有 AI 目标 | `无目标` | 空结果文字的功能含义。 |
| 触发者有生命值但不属于上述生物，例如玩家、盔甲架 | `该怪物不具备威胁度功能` | 不会查询施法者来代替。 |

**缺少触发者，或触发者不是有生命实体时，不保证返回上述文字。** 不要随便挂在出生、计时器或控制台技能调用上，假设它自然就知道要查询谁。

## 常见问题（功能含义，不是当前启用指南）

- **玩家攻击时为什么不是查村民？** `~onDamaged` 的触发者是攻击者。玩家攻击村民时查的是玩家，不是村民；玩家对应“不具备威胁度功能”的分支。
- **发给 `@target` 就能查 target 吗？** 不能。选择器决定技能作用对象或消息接收者，占位符仍读取事件触发者。
- **为什么空表也有名字？** 空表会读取生物当前的 AI 目标作为后备显示；这不是 MM 原生威胁表的第一名，也不能据此认定整个占位符安全。
- **“无目标”是什么意思？** 可能表和 AI 目标都为空，也可能最高分记录对应的实体已经找不到；后者仍经过危险查询，不能把兜底文字当作安全保障。
- **能否加 `sync=true` 解决？** 不能。主线程等待主线程任务正是风险所在；请等修复并验证，不要自行启用这些参考。
